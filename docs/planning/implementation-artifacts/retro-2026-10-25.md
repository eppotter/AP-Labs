## What the numbers don't show

1. **A false "merged" post.**
   - The Orchestrator chained `npm run notify -- --kind merged` after `npm run land` in one command. Land refused #124 because CI was red, and the "merged" post went to Slack anyway.
   - A correction was posted. Afterwards every notify ran only after land printed `Merged PR #<n>`.
2. **Ledger conflicts were resolved by hand, and badly.**
   - Merging main into a branch conflicts on `docs/ledger.md` almost every time.
   - Two hand resolutions left duplicate `#117` and `#119` rows. CI's ledger test caught both, which cost a CI run and a review round each time.
3. **The test fake let an impossible Slack view through.**
   - The architect's 9.3 design ("no Submit, buttons only") and the fake Slack client both allowed a modal with input blocks and no `submit`. Slack rejects that view.
   - The review caught it (P1 R1-1, confirmed from Slack's docs), and the fake now enforces the rule.
4. **`land` can't clear a fixed P1.**
   - A confirmed P1 stays counted on the PR's Refuter line after it is fixed and a later round on a newer head is clean.
   - #127 is blocked on this. The only way through today is a human merging by hand.
5. **Codex reviews fell back to Claude four times.**
   - The causes: a missing `codex-code-mode-host` on the new Mac (fixed), a BLOCKING verdict with only P2 lines, and missing verdict lines.
   - The cross-model check is only as good as its parser.

## What went well

- **Live checks before merge found three real bugs:** the FK upload order (#106), a share blocking `CREATE OR REPLACE DATABASE` (#122), and the reader's attachable `my_db` (#108, accepted by Ely). Throwaway-database tests settled each design question before any code was written.
- **The refuter cleared two false P1s** (#113, #124). The P2-before-merge rule caught real hardening (#120, #122, #125).

## Rules (added to `AGENTS.md`, the build loop)

- **Step 6:** post `notify --kind merged` only after `npm run land` prints `Merged PR #<n>`. Never chain it after land in the same command.
- **Step 3:** after merging main, resolve `docs/ledger.md` by keeping main's rows and adding only this branch's own row. Run the ledger tests (`node --test test/unit/ledger*.test.js`) before pushing.

## Follow-ups (issues)

- `land`: accept a confirmed P1 once a later review round on a newer head is clean, or give the human a recorded way to clear it. **Needs Ely's call; #127 is waiting.**
- The review parser: treat a BLOCKING verdict with no P1 line as malformed and re-ask once, instead of falling back to the same model.
- Test fakes: when a design depends on an external API's rules (Slack, MotherDuck), the fake enforces those rules, with a doc link in the fake.
